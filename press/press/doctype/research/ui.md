# Frontend UI — Architecture & Patterns

Vue 3 + Frappe UI dashboard. All data goes through Frappe UI resource primitives. All design uses Frappe UI components.

---

## Directory Structure

```
dashboard/src/
  objects/          ← object definitions (site.js, server.js, group.js, ...)
    common/         ← shared tab configs (apps, jobs, tags, patches)
    generateRoutes.js
  pages/            ← page components (ListPage, DetailPage, NewSite, ...)
  components/       ← 50+ shared UI components
  data/             ← singleton resources (team, plans, session, notifications)
  utils/            ← helpers (format, toast, resource creation)
  stores/           ← Pinia store (user state)
  router.js
  main.js           ← Frappe UI config + app boot
  globals.ts        ← global Vue properties ($team, $socket, etc.)
```

---

## When to Use Object.js vs a New .vue File

- **Object definition** (`objects/*.js`) — use for standard list + detail pages on an existing doctype. One file drives both pages, routing is auto-generated.
- **New `.vue` file** — use when the UI doesn't fit the list/detail template: multi-step wizards, standalone pages, custom dialogs, tab components with complex local state, or anything that needs logic the object pattern can't express. USe Frappe UI for that also.

Both approaches can coexist.

---

## Object Definition Pattern

Every entity (site, server, release group, etc.) is described by a plain JS object in `objects/`. This object drives both the list page and the detail page — no bespoke page components needed for standard entities.

### Minimal skeleton

```javascript
// objects/my-entity.js
export default {
  doctype: 'My Entity',

  whitelistedMethods: {
    doThing: 'do_thing',            // camelCase → snake_case backend method
    anotherAction: 'another_action',
  },

  list: {
    route: '/my-entities',
    title: 'My Entities',
    fields: ['status', 'team', 'plan.plan_title as plan_title'],
    orderBy: 'creation desc',
    searchField: 'name',
    filterControls() {
      return [
        {
          type: 'select',
          label: 'Status',
          fieldname: 'status',
          options: ['', 'Active', 'Inactive'],
        },
      ];
    },
    columns: [
      { label: 'Name', fieldname: 'name' },
      { label: 'Status', fieldname: 'status', type: 'Badge' },
    ],
    primaryAction({ listResource }) {
      return {
        label: 'New Entity',
        variant: 'solid',
        onClick() { router.push({ name: 'New My Entity' }); },
      };
    },
  },

  detail: {
    titleField: 'name',
    route: '/my-entities/:name',
    statusBadge({ documentResource: doc }) {
      return { label: doc.doc.status };
    },
    tabs: [
      {
        label: 'Overview',
        route: 'overview',
        type: 'Component',
        component: () => import('../components/MyEntityOverview.vue'),
        props: ({ documentResource: doc }) => ({ doc: doc.doc }),
      },
    ],
  },
};
```

Register in `objects/index.js`:
```javascript
import MyEntity from './my-entity.js';
export default { ..., MyEntity };
```

Routes are auto-generated by `generateRoutes.js` — no manual router entry needed.

---

## Routing

`generateRoutes()` reads every object and produces:

- **List route**: `{ path: object.list.route, component: ListPage, props: { objectType } }`
- **Detail route**: `{ path: object.detail.route, component: DetailPage, props: { objectType, name } }`
  - Each tab in `detail.tabs` becomes a child route

`objectType` string is passed as prop; pages call `getObject(objectType)` to retrieve the definition.

## Frappe UI Resources

### API endpoint config (set in `main.js`)

```javascript
setConfig('defaultListUrl',        'press.api.client.get_list');
setConfig('defaultDocGetUrl',      'press.api.client.get');
setConfig('defaultDocInsertUrl',   'press.api.client.insert');
setConfig('defaultRunDocMethodUrl','press.api.client.run_doc_method');
setConfig('defaultDocUpdateUrl',   'press.api.client.set_value');
setConfig('defaultDocDeleteUrl',   'press.api.client.delete');
```

All requests include `X-Press-Team` header (injected by the custom `request` wrapper).

### Document resource

Fetches a single doc and exposes whitelisted method calls:

```javascript
// In a component's resources block:
resources: {
  site() {
    return {
      type: 'document',
      doctype: 'Site',
      name: this.name,
      whitelistedMethods: {
        activate: 'activate',
        addDomain: 'add_domain',
        backup: 'schedule_backup',
      },
    };
  },
},
```

State exposed:
```javascript
this.$resources.site.doc          // document data object
this.$resources.site.loading      // Boolean
this.$resources.site.get.fetched  // Boolean
this.$resources.site.reload()     // re-fetch
```

Whitelisted method call:
```javascript
this.$resources.site.backup.submit(
  { with_files: true },
  {
    onSuccess: () => toast.success('Backup scheduled'),
    onError: (e) => toast.error(e.message),
  },
);
// or as promise:
await this.$resources.site.backup.submit({ with_files: true });
```

### List resource

```javascript
resources: {
  sites() {
    return {
      type: 'list',
      doctype: 'Site',
      fields: ['name', 'status', 'team'],
      filters: { status: 'Active' },
      orderBy: 'creation desc',
      pageLength: 20,
      auto: true,
    };
  },
},
```

State:
```javascript
this.$resources.sites.data      // array of rows
this.$resources.sites.loading   // Boolean
this.$resources.sites.hasNextPage
this.$resources.sites.next()    // load next page
this.$resources.sites.reload()
this.$resources.sites.update({ filters: { status: 'Broken' } })
```

### Arbitrary API call (non-doctype endpoint)

```javascript
import { createResource } from 'frappe-ui';

// In data() or setup():
this.getUsage = createResource({
  url: 'press.api.analytics.get_usage',
  params: { site: this.site },
  auto: true,
});

// Or call manually:
this.changeMode = createResource({ url: 'press.api.billing.change_payment_mode' });
await this.changeMode.submit({ mode: 'Prepaid Credits' });
```

### Cached document resource (singleton)

For resources shared across components (like the current team):

```javascript
import { getCachedDocumentResource } from 'frappe-ui';

computed: {
  $site() {
    return getCachedDocumentResource('Site', this.siteName);
  },
},
```

Global singletons (`$team`, `$session`) are set in `globals.ts` and available in all components via `this.$team`, `this.$session`.

## Calling Whitelisted Methods

Two ways:

### 1. Via `whitelistedMethods` in object definition (preferred for detail pages)

Defined in the object, automatically wired up by `DetailPage.vue`:

```javascript
// objects/site.js
whitelistedMethods: {
  loginAsAdmin: 'login_as_admin',
}

// In a tab component — documentResource is injected as prop:
site.loginAsAdmin.submit({}, { onSuccess: (data) => { window.open(data.url) } });
```

### 2. Via `resources` block in component

```javascript
resources: {
  enableScheduler() {
    return {
      url: 'press.api.client.run_doc_method',
      params: {
        dt: 'Site',
        dn: this.site,
        method: 'enable_scheduler',
      },
      onSuccess: () => this.$resources.site.reload(),
    };
  },
},
```

## Passing Data to Tab Components

`DetailPage.vue` passes the document resource to each tab via props:

```javascript
// In detail.tabs definition:
{
  label: 'Domains',
  route: 'domains',
  type: 'Component',
  component: () => import('../components/SiteDomains.vue'),
  props: ({ documentResource: site }) => ({
    site: site.doc.name,
    domains: site.doc.domains,
  }),
}
```

Inside the tab component, call methods via `getCachedDocumentResource` or accept the full resource as a prop.

---

## Real-Time Updates

`DetailPage.vue` subscribes to socket events on mount:

```javascript
this.$socket.emit('doc_subscribe', 'Site', this.name);
this.$socket.on('doc_update', (data) => {
  if (data.doctype === 'Site' && data.name === this.name) {
    this.$resources.document.reload();
  }
});
```

No manual setup needed for detail pages — it's in the base `DetailPage.vue`. For custom components outside detail pages, use `this.$socket` directly.

## UI Components

Always use Frappe UI components. Do not write bespoke HTML/CSS for standard patterns.

Key components available from `frappe-ui`:
- `Button`, `Badge`, `Tooltip`, `Input`, `FormControl`
- `Dialog`, `Alert`
- `Dropdown`, `Popover`
- `ListView`, `ObjectList`
- `Tabs`, `TabList`
- `Breadcrumbs`
- `LoadingIndicator`, `LoadingText`
- `FeatherIcon`

Press-specific shared components in `components/`:
- `ConfirmDialog` — confirmation pattern for destructive actions
- `ObjectList` — drives list pages
- `DetailPageControls` — header with actions for detail pages

## Toasts

```javascript
import { toast } from 'vue-sonner';

toast.success('Site activated');
toast.error('Failed to activate site');
toast.promise(site.activate.submit(), {
  loading: 'Activating...',
  success: 'Site activated',
  error: (e) => getToastErrorMessage(e),
});
```

`getToastErrorMessage(e)` from `utils/` extracts readable message from Frappe exception format.

## Exposing Methods & Fields to the Dashboard (Backend)

Three things must be in place for the dashboard frontend to access a doctype method or field.

### 1. ALLOWED_DOCTYPES

`press/api/client.py` has a module-level list:

```python
ALLOWED_DOCTYPES = [
    "Site",
    "Server",
    "Release Group",
    # ~100 more ...
]
```

Any doctype not in this list is invisible to the dashboard API endpoints (`get`, `get_list`, `run_doc_method`, `set_value`). Add your doctype here before wiring up anything else.

### 2. `@dashboard_whitelist` vs `@frappe.whitelist`

Two decorators — pick the right one:

| Decorator | Who can call it | Use when |
|-----------|----------------|----------|
| `@dashboard_whitelist()` | Dashboard frontend (via `run_doc_method`) | Method needs to be callable from `site.js` / `objects/*.js` `whitelistedMethods` |
| `@frappe.whitelist()` | Any authenticated Frappe session, server-side code | Internal API, called server-to-server, or not exposed to the dashboard |

Import path:
```python
from press.api.client import dashboard_whitelist
```

Usage:
```python
# Exposed to dashboard — frontend can call via documentResource.activate.submit()
@dashboard_whitelist()
def activate(self):
    """Activate the site."""
    ...

# Internal only — not callable from dashboard
@frappe.whitelist()
def _internal_sync(self):
    """Sync internal state."""
    ...
```

`dashboard_whitelist` wraps `frappe.whitelist` AND registers the method in the module-level `whitelisted_methods` set that `run_doc_method` checks before executing.

### 3. `dashboard_fields`

Controls which fields the dashboard can read or write via `get` / `set_value`. Declared as a class-level tuple on the doctype class:

```python
class Site(Document):
    dashboard_fields = (
        "name",
        "status",
        "team",
        "plan",
        "group",
        "server",
        "ip",
        # add new fields here when the dashboard needs them
    )
```

Fields not listed here are stripped from API responses — even if the doctype is in `ALLOWED_DOCTYPES`.

### Checklist: expose a new method

1. Doctype in `ALLOWED_DOCTYPES` in `press/api/client.py`.
2. Decorate method with `@dashboard_whitelist()` (not `@frappe.whitelist()`).
3. Add any new fields needed by the frontend to `dashboard_fields`.
4. Add method name to `whitelistedMethods` in the relevant `objects/*.js`.
5. Call via `documentResource.methodName.submit()` in the component.

---

## Adding a New Feature — Checklist

1. **Backend**: Add whitelisted method to doctype Python class with `@dashboard_whitelist()`.
2. **Backend**: Ensure doctype is in `ALLOWED_DOCTYPES`; add needed fields to `dashboard_fields`.
3. **Object definition**: Add to `whitelistedMethods` map in the relevant `objects/*.js`.
4. **Tab/component**: Use `documentResource.methodName.submit()` to call it.
5. **UI**: Use Frappe UI components — no raw HTML for standard patterns.
6. **List field**: If new field needed in list, add to `list.fields` + `list.columns`.
7. **No new routes**: Standard entities don't need manual router entries.
